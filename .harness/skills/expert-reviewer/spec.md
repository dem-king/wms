# Expert Reviewer Skill

## 触发条件

进入评审阶段时自动加载本 Skill。

## 评审职责

作为评审 Agent，你需要用**独立于编码 Agent 的检查视角**审视产出物。你不是在找茬，而是在确保质量。

## 两种评审模式

### 模式一：编码评审（Execution Review）

审查编码实现是否满足计划和需求。

**检查清单：**

1. [ ] 编码满足 `编码约束.md` 的所有规则？
2. [ ] spec.md 的验收标准全部覆盖？
3. [ ] 单元测试覆盖了核心业务路径？
4. [ ] 没有超出需求范围的过度重构？
5. [ ] Controller 注解完整（@PreAuthorize + @DataScope/@OperLog）？
6. [ ] 使用逻辑删除而非物理删除？
7. [ ] 没有 N+1 查询？
8. [ ] 编号生成使用 SequenceGenerator？
9. [ ] 库存操作有异常保护？

### 模式二：测试评审

审查测试用例的有效性。

**检查清单：**

1. [ ] 测试覆盖了正常路径和异常路径？
2. [ ] 测试数据具有业务代表性？
3. [ ] 测试互不依赖（可单独运行）？
4. [ ] 测试不依赖外部不可控状态？

## 评审报告模板

```markdown
# {变更名称} — 编码评审报告 v{编号}

## 评审结论
[APPROVED / REVISION REQUIRED]

## 问题清单

### #1 {问题简述} — MUST FIX / LOW / INFO
- **文件**: {文件路径}
- **行号**: {行号范围}
- **问题描述**: {描述}
- **修改建议**: {具体建议}

## 通过项
- [x] 安全注解完整
- [x] 逻辑删除正确
- [x] 无 N+1 查询
```

## 评审意见优先级

| 优先级 | 含义 | 处理 |
|--------|------|------|
| MUST FIX | 必须修复，否则无法通过 | 回退编码阶段 |
| LOW | 建议修复，不阻塞通过 | 记录，本次不阻塞 |
| INFO | 信息性备注 | 仅记录 |

## 评审循环控制

- 每轮评审最多产出 1 份报告
- 报告版本递增：v1, v2, v3
- 旧版本不删除
- 最多 2 轮循环，超出后升级人工决策
- 如果 0 个 MUST FIX，则 APPROVED → 进入下一阶段
