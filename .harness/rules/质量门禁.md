# 质量门禁规则

> 所有门禁条件必须可程序化验证。自然语言描述的质量要求对 Agent 无效。

---

## 一、CI 门禁（GitHub Actions 自动执行）

### 1.1 后端门禁

| 门禁项 | 判定条件 | 失败处理 |
|--------|---------|---------|
| 规则检查 | `scripts/check-rules.sh` exit code = 0 | 回退到编码阶段 |
| 编译与测试通过 | `mvn verify --batch-mode --no-transfer-progress -DskipTests=false` exit code = 0 | 编译错误回退到编码阶段，测试失败回退到测试编写阶段 |
| 测试覆盖率 > 0 | `total_tests > 0` | 回退到测试编写阶段 |
| 无编译警告 | `mvn verify` 无 WARNING（可选） | 记录但不阻断 |

### 1.2 前端门禁

| 门禁项 | 判定条件 | 失败处理 |
|--------|---------|---------|
| 类型检查 | `vue-tsc --noEmit` exit code = 0 | 回退到编码阶段 |
| 构建成功 | `npm run build` exit code = 0 | 回退到编码阶段 |
| 测试通过 | `vitest run` exit code = 0 | 回退到测试编写阶段 |

### 1.3 全局门禁公式

```
PASS = (rules.exit_code == 0)
    && (backend.verify == SUCCESS)
    && (backend.test.total > 0 && backend.test.passed == backend.test.total)
    && (frontend.typecheck == SUCCESS)
    && (frontend.build == SUCCESS)
    && (frontend.test.exit_code == 0)
```

## 二、代码审查门禁（Agent-to-Agent Review）

### 2.1 自动化规则扫描

> 可程序化规则已实现为 `scripts/check-rules.sh`，CI 每次 push 自动执行；人工审查项由 HITL 确认点补充。

| 规则扫描项 | 规则ID | 级别 |
|-----------|--------|------|
| 物理删除检查 | DB-01 | 🔴 阻断 |
| del_flag 冗余条件 | DB-02 | 🔴 阻断 |
| 逻辑删除使用常量 | DB-03 | 🔴 阻断 |
| 主键雪花ID | DB-04 | 🔴 阻断 |
| SQL 禁用 AUTO_INCREMENT | DB-05 | 🔴 阻断 |
| 循环内 mapper.insert | DB-06 | 🔴 阻断 |
| 查询最大编号+1 | SEQ-01 | 🔴 阻断 |
| @PreAuthorize 缺失 | SEC-01 | 🔴 阻断 |
| @DataScope 缺失 | SEC-02 | 🔴 阻断 |
| @OperLog 缺失 | SEC-03 | 🔴 阻断 |
| 配置文件硬编码 | SEC-04 | 🔴 阻断 |
| ServiceImpl 私有常量 | CONST-02 | 🔴 阻断 |
| 返回 Entity 非 Vo | ARCH-02 | 🔴 阻断 |
| private toVo 方法 | ARCH-03 | 🔴 阻断 |
| VO/DTO/Converter 命名 | NAME-03/04/05 | 🔴 阻断 |
| Entity 字段 @Schema | JAVADOC-01 | 🔴 阻断 |
| 类级 JavaDoc | JAVADOC-02 | 🔴 阻断 |
| 魔法数字 | CONST-01 | 🟡 警告 |
| N+1 查询 | PERF-01 | 🟡 警告 |

**执行方式**:
```bash
./scripts/check-rules.sh          # 阻断级违规 → exit 1
./scripts/check-rules.sh --strict # 警告也视为阻断
```

Windows 本地开发可使用 PowerShell 入口代理同一脚本（需要 Git Bash 或已安装 Linux 发行版的 WSL）：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/check-rules.ps1
powershell -ExecutionPolicy Bypass -File scripts/check-rules.ps1 --strict
```

### 2.2 评审循环上限

| 评审类型 | 最大轮次 | 超出处理 |
|---------|---------|---------|
| 编码评审 | 2 轮 | 升级到人工决策 |
| 复杂度 > 5 文件 | 3 轮 | 升级到人工决策 |

| 确认点 | 触发时机 | 确认内容 | 参考文档 |
|--------|---------|---------|---------|

## 四、回退路径（Rollback Routes）

```
CI 失败 →
  ├── 规则违规 → 回退到阶段 3（编码实现），修复违规代码
  ├── 编译错误 → 回退到阶段 3（编码实现）
  ├── 测试 0/0 → 回退到阶段 5（测试执行）
  ├── 测试失败 → 回退到阶段 5（测试执行）
  └── 需求不符 → 回退到阶段 1（需求分析）

编码评审失败 →
  ├── 自动化规则扫描失败 → 回退到阶段 3（编码实现）
  ├── HITL-2 人工审查不通过 → 回退到阶段 3（编码实现）
  └── HITL-4 人工审查不通过 → 回退到阶段 3（编码实现）
```
