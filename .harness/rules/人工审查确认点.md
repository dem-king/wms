# 人工审查确认点（HITL - Human-in-the-Loop）

> 以下确认点需要在关键阶段由人工进行审查确认，补充程序化验证无法覆盖的规范。

---

## HITL-1: 需求分析完成确认

**触发时机**：spec.md 编写完成，进入设计阶段前

**确认内容**：
- [ ] 用户故事清晰，包含角色、需求、价值
- [ ] 验收标准可测试、可验证
- [ ] 边界条件和异常场景已定义
- [ ] 与现有系统的交互关系已明确

**确认人**：产品经理 / 需求提出方

---

## HITL-2: 编码评审通过确认

**触发时机**：代码实现完成，CI 通过，进入合并前

**确认内容**：
- [ ] 代码符合分层架构规范（Controller 不含业务逻辑）
- [ ] 命名语义清晰，符合命名规范
- [ ] 复杂逻辑有适当的抽象和拆分
- [ ] 无明显的性能隐患（N+1 查询、全表扫描等）

**确认人**：技术负责人 / 代码审查者

---

## HITL-3: CI 验证通过确认

**触发时机**：CI 全部通过，进入部署前

**确认内容**：
- [ ] 后端编译、测试、覆盖率检查通过
- [ ] 前端类型检查、构建、单元测试通过
- [ ] 环境配置参数已确认（数据库连接、密钥等）
- [ ] 回滚策略已准备

**确认人**：DevOps / 发布负责人

---

## HITL-4: 代码质量与注释规范确认 ⭐ NEW

**触发时机**：编码评审阶段（与 HITL-2 并行或之后）

**审查范围**：本次变更涉及的所有文件

### 4.1 注释质量审查

#### 类级别 JavaDoc
- [ ] **所有 public 类**是否有 JavaDoc 注释
- [ ] 类注释是否准确描述**业务职责**（非"XX服务实现类"这类废话）
- [ ] 类注释是否说明**主要功能**和**使用场景**

**示例对比**：
```java
// ✅ 好注释：说明业务职责
/**
 * 入库单服务实现类
 * 处理入库单的创建、审核、完成等业务逻辑
 * 包含库存校验、单号生成、事件发布等操作
 */

// ❌ 坏注释：只说是什么，没说干什么
/**
 * 入库单服务实现类
 * 实现 InboundOrderService 接口
 */
```

#### 方法级别 JavaDoc
- [ ] **所有 public 方法**是否有 JavaDoc 注释
- [ ] 是否包含 `@param` 说明参数含义
- [ ] 是否包含 `@return` 说明返回值含义
- [ ] 复杂业务方法是否有**业务逻辑说明**

**示例对比**：
```java
// ✅ 好注释：说明业务功能和参数含义
/**
 * 创建入库单
 * 校验库房是否存在且启用，生成入库单号，保存入库单及明细
 *
 * @param dto 入库单创建参数，包含库房ID、供应商ID、明细列表
 * @return 创建后的入库单VO，包含生成的单号和初始状态
 */

// ❌ 坏注释：只说做了什么操作
/**
 * 创建入库单
 * @param dto 入参
 * @return 返回值
 */
```

#### 字段注释（Entity/DTO/VO）
- [ ] **所有字段**是否有 `@Schema` 注解
- [ ] `@Schema` 的 description 是否与数据库字段注释一致
- [ ] 字段上方是否有 JavaDoc 注释说明**业务含义**

**示例对比**：
```java
// ✅ 好注释：说明业务含义
/** 物品编码，全局唯一，格式：WP + 6位流水号 */
@Schema(description = "物品编码")
private String itemCode;

// ❌ 坏注释：与字段名重复，无额外信息
/** 物品编码 */
@Schema(description = "物品编码")
private String itemCode;
```

#### 关键逻辑行内注释
- [ ] **复杂条件判断**前是否有注释说明判断目的
- [ ] **业务规则处理**处是否有注释说明规则来源
- [ ] **特殊处理逻辑**处是否有注释说明原因

**示例对比**：
```java
// ✅ 好注释：说明"为什么"
// 校验库房是否存在且为启用状态（禁用库房禁止创建单据）
if (warehouse == null || warehouse.getStatus() == 0) {
    throw new BizException("库房不存在或已禁用");
}

// 生成入库单号：格式为RK + 年月日 + 4位流水号
String orderNo = sequenceGenerator.next("RK");

// 状态为待审核时，发布入库单创建事件（触发审批流程）
if (OrderStatus.PENDING_REVIEW.equals(dto.getStatus())) {
    eventPublisher.publishEvent(new InboundOrderCreatedEvent(orderNo));
}

// ❌ 坏注释：只说"是什么"
// 判断库房
if (warehouse == null) { ... }

// 生成单号
String orderNo = ...;

// 判断状态
if (status == 0) { ... }
```

### 4.2 数据库设计原则审查

#### 金额字段类型
- [ ] 所有**金额/价格/数量**字段使用 `BigDecimal`（Java）/ `DECIMAL`（SQL）
- [ ] 禁止使用 `Float` / `Double` / `FLOAT` / `DOUBLE`

**检查清单**：
```java
// ✅ 正确
private BigDecimal price;
private BigDecimal amount;
private BigDecimal totalCost;

// ❌ 错误
private Double price;
private Float amount;
```

```sql
-- ✅ 正确
`price` DECIMAL(10,2) NOT NULL COMMENT '单价',
`amount` DECIMAL(12,2) NOT NULL COMMENT '金额',

-- ❌ 错误
`price` FLOAT NOT NULL,
`amount` DOUBLE NOT NULL,
```

#### 时间字段类型
- [ ] 所有**时间字段**使用 `LocalDateTime`（Java）/ `DATETIME`（SQL）
- [ ] 禁止使用 `String` / `VARCHAR` 存储时间
- [ ] 时间戳字段是否有 `DEFAULT CURRENT_TIMESTAMP`

**检查清单**：
```java
// ✅ 正确
private LocalDateTime createTime;
private LocalDateTime updateTime;

// ❌ 错误
private String createTime;
```

```sql
-- ✅ 正确
`create_time` DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
`update_time` DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',

-- ❌ 错误
`create_time` VARCHAR(20) COMMENT '创建时间',
```

#### 外键约束控制
- [ ] 外键关联**仅在逻辑层控制**（代码校验）
- [ ] 数据库表**不建立物理外键约束**（FOREIGN KEY）
- [ ] 外键字段命名规范：`关联表名_id`（如 `warehouse_id`）

**检查清单**：
```sql
-- ✅ 正确：有外键字段，无物理外键约束
CREATE TABLE wms_inbound_order (
    `id` BIGINT NOT NULL COMMENT '主键',
    `warehouse_id` BIGINT NOT NULL COMMENT '库房ID',
    -- 无 FOREIGN KEY (warehouse_id) REFERENCES ...
);

-- ❌ 错误：建立物理外键约束
CREATE TABLE wms_inbound_order (
    `id` BIGINT NOT NULL,
    `warehouse_id` BIGINT NOT NULL,
    FOREIGN KEY (`warehouse_id`) REFERENCES `wms_warehouse`(`id`)
);
```

#### 状态字段设计
- [ ] 状态字段使用 `TinyInt` 类型
- [ ] 有对应的**枚举类**定义状态值含义
- [ ] 枚举值有 JavaDoc 说明

**检查清单**：
```java
/**
 * 入库单状态枚举
 */
public enum InboundOrderStatusEnum {
    /** 草稿 */
    DRAFT(0),
    /** 待审核 */
    PENDING_REVIEW(1),
    /** 已通过 */
    APPROVED(2),
    /** 已驳回 */
    REJECTED(3);
    
    private final int code;
}
```

### 4.3 审查通过标准

| 检查项 | 通过标准 | 处理方式 |
|-------|---------|---------|
| 类 JavaDoc | 100% 覆盖，内容有意义 | 不通过则补充 |
| 方法 JavaDoc | 100% 覆盖，参数/返回值说明清晰 | 不通过则补充 |
| 字段注释 | 100% 覆盖，与数据库一致 | 不通过则补充 |
| 行内注释 | 关键逻辑有注释 | 不通过则补充 |
| 金额字段类型 | 100% 使用 BigDecimal/DECIMAL | 不通过则修改 |
| 时间字段类型 | 100% 使用 LocalDateTime/DATETIME | 不通过则修改 |
| 外键约束 | 无物理外键约束 | 不通过则删除 |

### 4.4 审查工具建议

**辅助检查命令**：
```bash
# 检查缺少 JavaDoc 的 public 类
grep -r "^public class" --include="*.java" | grep -v "/target/"

# 检查缺少 @Schema 的 Entity 字段
grep -r "private.*;" wms-*/src/main/java/com/wms/*/domain/entity/ | grep -v "@Schema"

# 检查 Float/Double 类型（金额字段嫌疑）
grep -r "private Float\|private Double" --include="*.java" wms-*/src/main/java/

# 检查 String 类型的时间字段嫌疑
grep -r "private String.*[Tt]ime\|private String.*[Dd]ate" --include="*.java"
```

**确认人**：代码审查者 / 技术负责人

## 确认点触发流程

```
需求分析完成 → HITL-1 → 设计阶段
     ↓
编码实现完成 → HITL-2 + HITL-4 → 代码评审
     ↓
CI 验证通过 → HITL-3 → 部署发布
```
