# 编码约束规则

> 规则优先沉淀为可程序化验证条件；暂不能可靠自动化的约束必须进入 HITL 人工确认点。

| 规则ID | 规则 | 可程序化验证 | 对应 check-rules.sh |

## 二、数据操作规则（违反即阻断）

| 规则ID | 规则 | 可程序化验证 | 对应 check-rules.sh |
|--------|------|-------------|-------------------|
| DB-01 | 禁止物理删除 | 代码中不能有 `mapper.delete(wrapper)` / `mapper.deleteById` / `mapper.deleteBatchIds` | check_DB01 |
| DB-02 | 禁止手动拼接 del_flag=0 | 代码中不能有 `.eq(Xxx::getDelFlag, 0)` 或 `.eq("del_flag", 0)` | check_DB02 |
| DB-03 | 逻辑删除必须显式写 del_flag | 见下方「DB-03 详细说明」 | check_DB03 / check_DB07 |
| DB-04 | 主键必须用雪花 ID | Entity 主键必须有 `@TableId(type = IdType.ASSIGN_ID)` | check_DB04 |
| DB-05 | SQL 建表不含 AUTO_INCREMENT | DDL 文件中的主键定义不能含 `AUTO_INCREMENT` | check_DB05 |
| DB-06 | 批量插入必须用 saveBatch | 循环内不能有 `mapper.insert()`，必须用 `Db.saveBatch(list)` | check_DB06 |
| DB-07 | 禁止 setDelFlag+updateById / Db.updateBatchById 删除模式 | `@TableLogic` 字段在普通 update 路径中会被跳过，必须使用 LogicDeleteHelper 或 UpdateWrapper.set 显式写 del_flag | check_DB07 |

#### DB-03 / DB-07 详细说明（红线规则）

`delFlag` 字段标注了 `@TableLogic`，MyBatis-Plus 对逻辑删除字段有特殊处理：**`setDelFlag(DELETED) + updateById` 与 `Db.updateBatchById` 这两类路径可能不会真正写入 `del_flag=1`**，会导致"前端点击删除后数据仍然存在"。

```java
// ✅ 正确：使用统一逻辑删除工具，显式更新 del_flag 字段
LogicDeleteHelper.markDeleted(mapper, WmsXxxEntity.class, id);
LogicDeleteHelper.markDeletedEntities(mapper, WmsXxxEntity.class, entities);

// ✅ 正确：显式 set del_flag，避免 @TableLogic 字段被普通更新跳过
mapper.update(null, Wrappers.<WmsXxxEntity>lambdaUpdate()
        .set(WmsXxxEntity::getDelFlag, DelFlagConstants.DELETED)
        .eq(WmsXxxEntity::getId, id));

// ❌ 错误（DB-07）：逻辑删除字段可能不会被写入数据库
entity.setDelFlag(DelFlagConstants.DELETED);
mapper.updateById(entity);

Db.updateBatchById(updateList);
```

适用范围：主表、关联表、单据明细、报表旧记录清理等所有需要逻辑删除的数据。

## 四、硬编码与常量规则

| 规则ID | 规则 | 可程序化验证 | 对应 check-rules.sh |
|--------|------|-------------|-------------------|
| CONST-01 | 禁止魔法数字（状态值/类型值/标志位） | 扫描 `= 0` / `= 1` 等赋值，排除定义行和循环变量 | check_CONST01 |
| CONST-02 | ServiceImpl 中禁止私有常量 | ServiceImpl 中不能有 `private static final` 定义 | check_CONST02 |
| **CONST-03** | **常量类位置合规** | 公共常量必须放 `wms-common.constant`；模块常量必须放 `module.domain.constant`；不在 ServiceImpl/Controller 中定义 `public static final` 业务常量 | check_CONST03 |
| CONST-04 | BizException 异常信息必须精确 | 同类场景不能合并异常信息（如 "库房不存在或已禁用" 应拆为两条） | 人工审查 |

#### CONST-03 详细说明

```java
// ✅ 正确：公共常量放 wms-common
package com.wms.common.constant;
public final class DelFlagConstants {
    public static final int DELETED = 1;
}

// ✅ 正确：模块常量放模块的 domain.constant
package com.wms.item.domain.constant;
public final class ItemConstants {
    public static final String ITEM_NO_PREFIX = "WP";
}

// ❌ 错误：业务常量散落在 ServiceImpl/Controller 中
public class InboundServiceImpl {
    public static final String ORDER_NO_PREFIX = "RK";  // 必须提到 OrderConstants
}
```
