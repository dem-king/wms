# WMS UI 风格迁移设计

## 背景

`wms-web` 已具备完整的后台布局能力，包括侧栏、顶部导航、标签页、偏好抽屉、主题切换与暗色模式。但当前布局层的整体风格仍偏向原生 Element Plus 组合：

- 顶部工具区是零散图标和文本组合，缺少统一的工具栏语言
- 标签页仍是基础 `el-tag` 形态，产品感和层次感较弱
- 用户信息区只有图标和用户名，没有头像卡片与清晰的下拉结构
- 偏好抽屉的能力和信息架构偏轻，无法承接“自由设置布局和外观”的预期
- 亮暗主题虽然可切换，但顶部、侧栏、标签栏和弹层之间没有形成统一风格

参考项目 `aryn-mall-ui` 提供了更成熟的后台壳层风格：圆润、卡片化、低噪音、蓝系高亮、顶部工具区组织清晰、标签页更接近浏览器页签形态、偏好抽屉具备完整配置分区。

## 目标

- 以 `aryn-mall-ui` 的整体 UI 风格为标准，重塑 `wms-web` 的后台壳层观感
- 完整升级顶部区域，包括菜单区、标签页、用户信息、偏好入口和暗色模式入口
- 将“可自由设置”的能力真正体现在偏好抽屉中，而不是只保留少量开关
- 在保留现有业务菜单、权限、路由和偏好持久化机制的前提下完成风格迁移
- 让亮色与暗色在布局层具备一致的层次、边界和交互反馈

## 非目标

- 本轮不重写业务页面内容区的全部业务组件
- 本轮不引入 `aryn-mall-ui` 的完整组件库和底层框架
- 本轮不变更现有动态菜单来源、权限结构和登录流程
- 本轮不追求与参考项目源码实现一比一一致，只追求风格、结构和交互体验对齐

## 方案选择

采用“在现有架构上做完整迁移”的方案。

理由如下：

- `wms-web` 已有成熟的偏好状态、主题变量和多布局模式，不需要推倒重来
- 当前最需要迁移的是布局层视觉和交互组织，而不是业务数据流
- 直接替换为参考项目技术体系成本过高，也会破坏现有权限和菜单逻辑

## 设计原则

### 1. 壳层优先

优先改造后台壳层，包括：

- `DefaultLayout`
- 顶部工具区
- 标签页
- 偏好抽屉
- 侧栏和顶部菜单的激活态
- 用户信息下拉

这样可以在不大量触碰业务页面的情况下，快速完成整体观感升级。

### 2. 风格对齐而非源码照搬

本次迁移不复制 `aryn-mall-ui` 的底层组件实现，而是抽取它的设计特征：

- 蓝系主色和更柔和的高亮背景
- 更统一的圆角和阴影体系
- 低噪音的边框和背景分层
- 顶部工具按钮的统一尺寸、悬浮态和间距
- 类 Chrome 页签的标签栏样式
- 头像卡片式用户下拉
- 分区清晰的偏好抽屉

### 3. 数据流不动，表现层重做

以下能力保持不变：

- 菜单树仍由现有权限系统驱动
- 路由缓存和页面切换逻辑继续沿用现有实现
- 偏好状态仍由 `preferences` 与 `updatePreferences()` 驱动
- 暗色模式仍基于 CSS 变量和 `documentElement` 状态切换

## 视觉系统调整

### 色彩

- 主色切换为更贴近参考项目的蓝系高亮
- 顶部工具按钮、激活标签页、菜单高亮、主操作按钮都统一使用蓝色语义
- 亮色模式下弱化纯白与纯灰对比，增加浅蓝和浅中性色过渡
- 暗色模式下保留清晰边界，但避免过重的纯黑和生硬反差

### 圆角和层次

- 顶部工具按钮、标签页、用户头像按钮、抽屉内部卡片采用统一圆角
- 顶栏、标签栏、下拉层、抽屉块采用一致的边框和阴影强度
- 背景层次调整为“页面底色 / 壳层底色 / 卡片底色 / 高亮底色”四层

### 交互

- 顶部 icon 按钮采用统一 hover 和 active 反馈
- 标签页激活态提升辨识度，非激活态降低噪音
- 用户区和偏好入口改成更明确的点击区域，而不是裸图标
- 暗色切换和偏好设置的交互区域统一为工具组

## 模块设计

### 1. 顶部区域

顶部区域调整为三段式结构：

- 左侧：Logo、侧栏折叠按钮、面包屑
- 中间：顶部菜单或留空弹性区
- 右侧：主题切换、偏好设置、全局工具、用户头像下拉

右侧工具区的视觉规则统一：

- 相同尺寸的圆角按钮容器
- 一致的 hover 背景和文字高亮
- 更明确的点击热区
- 在暗色模式下同步切换按钮底色和边框

### 2. 标签页

标签页从当前基础 `el-tag` 升级为更接近参考项目的标签栏：

- 激活标签页拥有明显的主色浅底和更强的层次
- 非激活页签使用轻量背景和更柔和边框
- 鼠标 hover 提供轻微提亮反馈
- 关闭按钮与标签内容形成统一布局
- 右侧补充“更多”和“内容最大化”工具入口

本轮不强制引入复杂拖拽体系，但标签栏视觉和工具结构要先对齐参考项目。

### 3. 用户信息区

用户区升级为头像入口：

- 顶部常驻区域展示头像、昵称和下拉箭头
- 下拉面板头部展示头像、用户名和附加描述
- 下拉菜单延续当前项目已有操作，至少保留“修改密码”和“退出登录”
- 如已有头像字段则优先展示头像，无头像则生成默认头像占位

### 4. 偏好设置入口与抽屉

偏好入口纳入顶部工具组，外观与暗色模式按钮一致。

偏好抽屉从当前“外观 / 布局”双标签升级为更清晰的分区结构，至少包含：

- 外观：主题模式、内置主题、主色、圆角
- 布局：布局模式、顶栏、侧栏、页脚
- 组件：标签页能力、工具按钮显隐、偏好按钮位置

其中“可自由设置”的重点能力包括：

- 标签页显示开关
- 标签页样式和高度
- 顶栏模式与菜单对齐
- 侧栏宽度、混合宽度、折叠与悬停展开
- 页脚显示开关
- 顶部工具按钮显隐
- 偏好按钮位置

### 5. 暗色模式

暗色模式不再只停留在变量切换，而是同步覆盖壳层风格：

- 顶栏背景、边框和按钮 hover 态跟随暗色语义
- 标签栏在暗色模式下仍保有明确激活态
- 下拉菜单和偏好抽屉的层次与背景统一
- 亮暗主题切换时避免顶部区域出现局部浅色残留

## 风险与处理

### 1. 业务页面与新壳层留白不一致

处理方式：

- 本轮只保证布局层整体视觉统一
- 业务页内部留白维持兼容，不做全量重写

### 2. 标签页功能配置与实际能力不一致

处理方式：

- 优先补齐可直观看到的配置项
- 暂不支持的高级能力不在抽屉中暴露，避免“能设置但无效果”

### 3. 亮暗模式下局部组件颜色写死

处理方式：

- 壳层组件全部改为 token 驱动
- 对于发现的写死色值，优先修正布局层和新增组件

## 验收标准

- 顶部区域整体风格明显对齐 `aryn-mall-ui`，具备统一工具栏视觉
- 标签页从基础标签样式升级为更强产品感的页签样式
- 用户信息区域具备头像入口和结构化下拉面板
- 偏好抽屉可见的配置项明显增加，并能真实驱动布局层变化
- 蓝系主色在亮色和暗色模式下都具备一致表现
- 不破坏现有菜单、权限、路由和业务页面访问能力
