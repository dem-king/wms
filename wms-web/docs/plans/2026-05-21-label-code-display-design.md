# Label Code Display Design

**背景**

标签管理页原本使用占位式图形模拟二维码与条形码，无法满足详情查看、打印预览和后续扫码链路对“真实可识别编码”的要求。本次设计目标是在不影响现有标签生成、绑定、打印状态更新流程的前提下，统一编码展示规则并引入真实渲染。

**方案选择**

方案一是直接在各个页面里分别根据 `labelType` 判断并调用不同图形库，改动快但会把兜底逻辑散落到多个视图中。方案二是把“标签数据解析”和“编码图形渲染”拆成两层，前者输出 `render/text/error` 三态，后者只负责根据明确入参完成二维码或条形码渲染。最终采用方案二，因为它更容易做单测，也能保证详情与打印预览的行为一致。

**组件边界**

- `src/views/label/code-display.ts` 负责解析 `ElectronicLabelVo`，统一决定当前标签应该渲染二维码、条形码、RFID 文本还是错误提示。
- `src/components/QrBarCode/rendering.ts` 负责对组件入参做空值规范化，并返回显示可读文本等元数据。
- `src/components/QrBarCode/index.vue` 负责真实渲染，二维码使用 `qrcode` 生成 data URL，条形码使用 `jsbarcode` 输出 SVG。
- `src/views/label/index.vue` 和 `src/views/label/components/LabelPrint.vue` 只消费解析结果，不再自行拼接不同场景下的兜底内容。

**展示规则**

- 二维码标签优先使用 `qrContent`，条形码标签优先使用 `barcodeContent`。
- RFID 标签不渲染二维码或条形码，只展示 RFID 编码文本。
- 编码内容为空或类型不支持时，页面展示明确错误提示，不输出任何可能被误认为有效码图的占位图。
- 打印预览中如存在无法渲染的标签，逐条显示警告信息并禁用打印按钮，避免错误内容进入打印版面。

**类型与异常处理**

- `ElectronicLabelVo` 中与绑定和编码相关的字段调整为可空类型，匹配后端真实返回。
- 标签列表查询参数提取为 `LabelListParams`，避免接口层重复内联类型。
- 标签详情加载失败时给出用户可见错误提示，渲染阶段的第三方库异常也显示统一失败文案。

**验证策略**

- 使用 Vitest 为规则层补充单测，覆盖二维码、条形码、RFID 和未知类型的解析分支。
- 增加 API 请求形状测试，确保打印状态更新接口未被改坏。
- 执行 `npm test -- ...` 与 `npm run build` 作为本次变更的相关验证。
