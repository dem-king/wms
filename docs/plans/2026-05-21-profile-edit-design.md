# 个人资料编辑与头像更换设计

**日期：** 2026-05-21

**目标：** 在现有个人中心基础上，为当前登录用户增加“编辑个人资料”能力，支持修改真实姓名、手机号、邮箱，并支持本地上传新头像后立即预览、保存和同步刷新顶部导航与个人中心展示。

## 现状

- 个人中心页面 `wms-web/src/views/profile/index.vue` 当前仅支持查看资料、查看最近登录信息和进行安全操作。
- 顶部导航与个人中心展示都依赖 `userStore.userInfo` 或 `/auth/profile` 返回的资料快照。
- 后端已支持查询当前用户个人中心资料 `GET /auth/profile`，但还没有自助修改资料或上传头像的接口。
- 系统用户模块已有通用用户实体字段：`realName`、`phone`、`email`、`avatar`，说明资料落库基础已经具备。

## 方案

### 交互形态

- 采用 `方案 A：个人中心页内联编辑 + 本地上传头像`。
- 在个人中心页面新增“资料编辑”卡片，包含资料表单和头像上传区域。
- 用户可在同一页面完成查看、编辑、保存，无需跳转到独立编辑页或打开弹窗。

### 页面结构

- 保留现有 `账号概览`、`基础资料`、`登录信息`、`账户摘要`、`安全中心`。
- 新增 `编辑资料` 区块：
  - `真实姓名`
  - `手机号`
  - `邮箱`
  - `头像上传`
- 头像区支持：
  - 显示当前头像或默认首字母占位
  - 选择本地图片文件
  - 上传前本地预览
  - 上传成功后回写头像 URL

### 数据流

- 页面初始化：
  - 调用 `/auth/profile` 获取当前资料
  - 表单默认值从返回数据中填充
- 编辑资料保存：
  - 调用 `PUT /auth/profile`
  - 请求体包含 `realName`、`phone`、`email`、`avatar`
- 头像上传：
  - 先调用 `POST /auth/profile/avatar`
  - 服务端返回头像 URL
  - 前端将该 URL 写入编辑表单，再统一通过资料保存接口提交
- 保存成功后：
  - 重新调用 `/auth/profile`
  - 同步更新 `userStore.userInfo`
  - 顶部头像、用户名、个人中心展示实时刷新

### 前端实现

- 新增资料编辑表单状态和校验规则：
  - `realName` 必填
  - `phone` 按手机号格式校验
  - `email` 按邮箱格式校验
- 使用 Element Plus 上传能力处理头像选择与上传。
- 上传成功前仅做本地预览，不直接修改 `userStore`。
- 资料保存成功后，统一刷新数据，避免局部状态不一致。

### 后端实现

- 在 `wms-auth` 模块新增接口：
  - `PUT /auth/profile` 更新当前登录用户个人资料
  - `POST /auth/profile/avatar` 上传当前登录用户头像
- Controller 仅负责鉴权、入参校验和调用 Service。
- Service 负责：
  - 获取当前登录用户 ID
  - 更新当前用户资料
  - 返回更新后的个人中心资料或头像地址
- 资料更新只允许修改当前登录用户，不允许传入任意用户 ID。

### 头像上传策略

- 首版采用“本地上传后返回可访问 URL”的方式。
- 如果项目已有统一文件上传链路，则优先复用。
- 若当前仓库没有现成公共上传能力，则在认证模块中实现最小可用上传出口：
  - 限制图片类型：`png/jpg/jpeg/webp`
  - 限制大小：例如 `2MB`
  - 保存到应用静态可访问目录或约定上传目录
  - 返回最终头像 URL

### 用户体验

- 上传头像后立即显示预览，减少保存前不确定感。
- 保存成功后弹出明确成功提示。
- 保存失败、上传失败、格式不合法都给出明确错误提示，不静默失败。
- 如果用户取消编辑，表单恢复到最近一次加载的数据。

### 测试策略

- 前端先补结构测试，覆盖：
  - 编辑资料区域
  - 头像上传标记
  - 保存资料动作
  - 资料刷新与 `userStore` 同步标记
- 后端补聚焦测试，覆盖：
  - 当前用户资料更新
  - 最近资料返回刷新
  - 非法头像上传被拒绝
- 完成后执行：
  - 前端 `npm test`
  - 前端 `npm run build`
  - 后端聚焦测试

## 不做范围

- 不做头像裁剪、旋转、压缩等高级编辑能力。
- 不做多头像历史管理。
- 不做管理员代替用户编辑个人资料。
- 不做第三方对象存储适配的完整抽象层，首版先满足当前项目可用实现。
