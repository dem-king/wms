# 备品备件库房管理平台 - 项目架构与开发文档

---

## 一、项目概述

### 1.1 项目名称

备品备件库房管理平台（WMS - Warehouse Management System）

### 1.2 建设目标

实现备品备件、消耗品、维修用品、体育用品、医疗用品等物资从**入库→存放→领用→审批→归还→报废→调拨→统计→预警→溯源**的全过程闭环管理。

### 1.3 核心能力

| 能力 | 说明 |
|------|------|
| 可视化 | 2D/2.5D库房图形展示，所见即所得 |
| 闭环管理 | 入库-存放-领用-归还-报废-调拨全流程 |
| 电子标签 | 二维码/条形码/RFID识别，物品唯一标识 |
| 审批流 | 多级审批、免审配置、限时审批 |
| 库存预警 | 上下限预警、消耗品补货提醒、长期闲置标记 |
| 权限管控 | RBAC模型、分级账户、数据范围控制 |
| 操作留痕 | 全业务操作日志，责任可追溯 |
| 报表导出 | Excel/PDF双格式，自定义报表字段 |

### 3.2 分层架构规范

```
Controller → Service → Mapper → DB
   │           │
   │           └── Event Publish (库存同步/预警触发)
   │
   └── @OperLog (操作日志AOP)
   └── @DataScope (数据范围AOP)
   └── @PreAuthorize (权限校验)
```

| 层 | 职责 | 规范 |
|----|------|------|
| Controller | 接口入参校验、路由、调用Service | 仅做参数校验(@Valid)和调用转发，不含业务逻辑 |
| Service | 核心业务逻辑、事务控制 | 事务注解@Transactional标注在写方法上，复杂逻辑抽取private方法 |
| Mapper | 数据访问 | 继承MyBatis-Plus BaseMapper，复杂查询写XML |
| Domain | 实体/DTO/VO | entity对应表，dto接收入参，vo返回出参，converter做转换 |
| Event | 领域事件 | 业务操作后发布事件(库存同步/标签更新/预警触发)，解耦主流程 |

## 五、API接口规范

### 5.1 接口风格

- RESTful风格，模块化路径
- 统一前缀: `/api/v1`
- 认证方式: Bearer Token (JWT)

### 5.2 统一响应体

```json
{
    "code": 200,
    "msg": "操作成功",
    "data": {}
}
```

| code | 含义 |
|------|------|
| 200 | 成功 |
| 401 | 未认证 |
| 403 | 无权限 |
| 400 | 业务异常 |
| 500 | 系统异常 |

### 5.3 分页请求/响应

```
GET /api/v1/items?page=1&size=20&sort=createTime,desc
```

```json
{
    "code": 200,
    "data": {
        "records": [],
        "total": 100,
        "page": 1,
        "size": 20
    }
}
```

## 六、核心业务流程

### 6.1 入库流程

```
物品到货 → 入库登记(手动/扫码/批量)
    ↓
生成/绑定电子标签 → 分配存放柜/库位
    ↓
是否需要审批？ ──否──→ 直接入库
    │                        ↓
    是                   库存增加 → 标签状态更新
    ↓                        ↓
提交审批 → 审批通过？        库房图形同步更新
    │                        ↓
  通过/驳回              入库记录留痕
```

### 6.2 出库/领用流程

```
发起领用 → 填写领用信息(物品/数量/用途/领用人)
    ↓
是否消耗品？ ──是──→ 领用后直接扣减库存，不要求归还
    │                        ↓
    否                   低于阈值触发补充提醒
    ↓
是否需要归还？ ──否──→ 直接出库扣减
    │
    是
    ↓
设置借出期限/预计归还时间
    ↓
是否需要审批？ ──否──→ 直接出库
    │
    是
    ↓
提交审批 → 审批通过 → 扫码/手动出库
    ↓
扣减库存 → 标签状态→"正在使用" → 关联领用人
```

### 6.3 归还流程

```
归还登记 → 核对借出记录
    ↓
归还状态？ ──正常──→ 恢复库存 → 标签状态→"已归还"
    │
  异常(损坏/丢失/数量不符)
    ↓
登记异常 → 关联责任人 → 转异常处理流程
    ↓
归还记录留痕
```

### 6.4 报废流程

```
发起报废申请 → 填写报废原因
    ↓
审批(多级) → 审批通过
    ↓
库存扣减 → 物品状态→"报废" → 标签状态→"报废"
    ↓
报废记录归档
```

### 6.5 调拨流程

```
发起调拨 → 选择调出位置/调入位置
    ↓
审批 → 审批通过
    ↓
更新存放位置 → 更新库房图形 → 库存归属变更
    ↓
生成调拨记录
```

## 七、开发规范

### 7.1 后端编码规范

#### 命名规范

| 类型 | 规范 | 示例 |
|------|------|------|
| 包名 | 全小写 | com.wms.system.service |
| 类名 | 大驼峰 | SysUserController |
| 方法名 | 小驼峰 | getUserById |
| 常量 | 全大写下划线 | MAX_RETRY_COUNT |
| 数据库表 | 小写下划线 | sys_user |
| 数据库字段 | 小写下划线 | create_time |

#### 分层调用规范

- Controller仅做参数校验和调用Service，不含业务逻辑
- Service处理业务逻辑，事务注解标注在写方法上
- 禁止Controller直接调用Mapper
- 禁止Service间循环依赖，抽取公共逻辑到common

#### 逻辑删除规范

- 所有实体继承`BaseEntity`，MyBatis-Plus全局配置逻辑删除
- 查询自动拼接`del_flag=0`条件
- 删除操作实际执行`UPDATE SET del_flag=1, last_oper_type='d'`

#### 操作日志规范

- 关键业务操作标注`@OperLog`注解
- 注解属性: module(模块), type(操作类型), desc(描述)
- AOP切面自动记录操作人、IP、参数、耗时

#### 数据范围规范

- 需要数据隔离的查询方法标注`@DataScope`注解
- AOP切面根据用户角色自动拼接SQL条件

### 7.2 前端编码规范

#### 组件规范

- 页面组件使用`<script setup lang="ts">`
- 组件命名大驼峰，文件命名小驼峰或kebab-case
- Props定义使用`defineProps<T>()` + `withDefaults`
- 事件使用`defineEmits<T>()`

#### 状态管理规范

- 全局状态(Pinia): 用户信息、权限菜单、应用配置
- 局部状态: 组件内ref/reactive
- 禁止在组件中直接操作localStorage，通过工具函数封装

#### API调用规范

- 所有API调用通过`src/api/`统一管理
- 使用`request.ts`封装的Axios实例
- 接口函数返回类型明确声明

#### 权限控制规范

- 路由级: 动态路由根据用户菜单权限生成
- 按钮级: 使用`v-permission`指令或`usePermission`钩子
- 数据级: 后端@DataScope注解控制

### 7.3 Git规范

#### 分支策略

```
main          ← 生产分支
  └── develop ← 开发主分支
        ├── feature/P1-item-archieve    ← 功能分支
        ├── feature/P2-warehouse-visual
        ├── feature/P3-approval-flow
        ├── fix/stock-sync-bug          ← 修复分支
        └── release/v1.0.0             ← 发布分支
```

#### Commit规范

```
<type>(<scope>): <subject>

type: feat | fix | refactor | docs | style | test | chore
scope: system | warehouse | item | business | approval | report | monitor
示例: feat(business): 新增入库单扫码入库功能
```

### 7.4 接口文档规范

- 使用Knife4j(Swagger增强)自动生成API文档
- 每个Controller添加`@Tag`注解
- 每个接口添加`@Operation`注解
- DTO/VO字段添加`@Schema`注解
