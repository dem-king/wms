# 物品库位关联实现计划

## Summary

- 目标：让物品档案支持绑定多个库位，并在物品列表中展示当前绑定库位；新增/编辑物品时可跨多个仓库选择多个库位。
- 方案：新增独立的“物品-库位关联”表，专门表达档案层的库位配置，不复用 `wms_stock`，避免污染真实库存语义。
- 范围：数据库脚本、`wms-item` 后端接口与聚合查询、前端物品列表页和表单、最小必要测试与验证。
- 非范围：不改动真实库存同步规则、不改入库/出库/归还的库存扣增逻辑、不顺手重构当前物品页已有的其它字段漂移问题。

## Current State Analysis

### 1. 现有数据模型

- `wms-server/wms-item/src/main/java/com/wms/item/domain/entity/WmsItem.java`
  - 物品主表只存档案信息，没有库位关联字段。
- `wms-server/wms-item/src/main/java/com/wms/item/domain/entity/WmsStock.java`
  - 库存表已包含 `itemId`、`warehouseId`、`areaId`、`cabinetId`、`binId`、`quantity`。
- `wiki/业务开发/物品库存.md`
  - 明确说明 `WmsStock` 由业务单据提交后的 `StockSyncEvent` 同步创建/更新，属于真实库存记录。
- `database/wms_ddl.sql`
  - `wms_stock` 上已有 `uk_item_bin(item_id, bin_id, del_flag)` 唯一约束，进一步证明它语义是“某物品在某库位上的库存记录”而不是档案配置。

### 2. 现有后端接口

- `wms-server/wms-item/src/main/java/com/wms/item/controller/ItemController.java`
  - 目前只有物品分页、详情、增删改、图片、快速搜索。
- `wms-server/wms-item/src/main/java/com/wms/item/service/impl/ItemServiceImpl.java`
  - 分页和详情只补充类目、标签、图片，没有库位聚合。
- `wms-server/wms-warehouse/src/main/java/com/wms/warehouse/controller/BinController.java`
  - 只支持按存放柜查库位，没有“跨仓库获取可选库位”的查询接口。
- `wms-server/wms-item/pom.xml`
  - `wms-item` 当前未依赖 `wms-warehouse`，不能直接复用仓库模块实体/Mapper。

### 3. 现有前端页面

- `wms-web/src/views/item/list/index.vue`
  - 列表未展示库位，表单也没有库位选择控件。
  - 编辑逻辑当前直接用列表行数据回填，而不是先请求详情。
- `wms-web/src/api/item/item.ts`
  - 没有库位选项接口。
- `wms-web/src/types/item.d.ts`
  - `WmsItemDto`/`WmsItemVo` 没有库位相关字段。
- `wms-web/src/api/warehouse/warehouse.ts`、`area.ts`、`cabinet.ts`、`bin.ts`
  - 现有 API 可拿库房/区域/存放柜/库位，但要拼出“跨仓多库位选择”需要多次串行请求，不适合作为物品表单的直接数据源。

## Assumptions & Decisions

- 决策 1：使用独立关联表，不复用 `wms_stock`。
  - 原因：用户已明确选择独立关联表；同时这也符合当前库存事件流，避免为了“预配置库位”创建零库存记录。
- 决策 2：允许一个物品绑定多个仓库下的多个库位。
  - 结果：前端表单不能做“单仓库 + 多库位”的强约束，选项数据必须自带完整仓库路径。
- 决策 3：库位绑定只代表“档案层当前配置/可放置位置”，不直接修改 `wms_bin.isOccupied`、`usedCapacity`、`wms_stock`。
  - 原因：这三个字段当前更接近真实占用与库存状态，不能被档案编辑动作提前污染。
- 决策 4：库位选项只返回有效库位。
  - 有效定义：库位、存放柜、区域、库房均未逻辑删除，且库位状态为启用/正常可用。
- 决策 5：列表页显示摘要，详情页返回完整库位数组。
  - 原因：分页列表只需要可读展示；编辑表单需要完整 `binIds` 与路径标签。

## Proposed Changes

### 一、数据库改造

#### 1. 新增增量脚本

- 新增：`database/migration/V20260528__add_item_bin_relation.sql`
- 作用：
  - 创建 `wms_item_bin` 表，仅保存 `id`、`item_id`、`bin_id`、`del_flag`、公共审计字段。
  - 增加唯一索引 `uk_item_bin(item_id, bin_id, del_flag)`。
  - 增加常用索引 `idx_item_id`、`idx_bin_id`。
- 关键约束：
  - 主键继续使用雪花 ID。
  - 只做逻辑删除，不做物理删除。
  - 不冗余保存 `warehouse_id/area_id/cabinet_id`，这些信息从 `wms_bin -> wms_cabinet -> wms_area -> wms_warehouse` 推导，避免双写一致性问题。

#### 2. 同步初始化脚本

- 修改：`database/wms_ddl.sql`
- 修改：`database/wms_full_init.sql`
- 作用：
  - 将 `wms_item_bin` 纳入标准建表与完整初始化。
  - 保持公共字段、索引、注释规范与现有表一致。

### 二、后端模型与依赖改造

#### 1. 模块依赖

- 修改：`wms-server/wms-item/pom.xml`
- 变更：
  - 增加对 `wms-warehouse` 的模块依赖。
- 原因：
  - 物品模块需要直接读取 `WmsWarehouse`、`WmsArea`、`WmsCabinet`、`WmsBin` 及其 Mapper 做批量聚合查询。

#### 2. 新增关联实体与 Mapper

- 新增：`wms-server/wms-item/src/main/java/com/wms/item/domain/entity/WmsItemBin.java`
- 新增：`wms-server/wms-item/src/main/java/com/wms/item/mapper/WmsItemBinMapper.java`
- 设计：
  - `WmsItemBin` 继承 `BaseEntity`。
  - 字段仅保留 `itemId`、`binId` 与公共字段。
  - JavaDoc 和字段中文注释补齐。

#### 3. 新增前后端契约 VO

- 新增：`wms-server/wms-item/src/main/java/com/wms/item/domain/vo/ItemBinVo.java`
- 新增：`wms-server/wms-item/src/main/java/com/wms/item/domain/vo/ItemBinOptionVo.java`
- 设计：
  - `ItemBinVo`：用于物品详情/列表返回，至少包含 `binId`、`binCode`、`cabinetId`、`cabinetName`、`areaId`、`areaName`、`warehouseId`、`warehouseName`、`displayLabel`。
  - `ItemBinOptionVo`：用于表单多选下拉，可复用上面的核心字段，并显式返回 `value=binId`、`label=displayLabel`。

#### 4. 扩展物品 DTO/VO

- 修改：`wms-server/wms-item/src/main/java/com/wms/item/domain/dto/ItemDto.java`
- 修改：`wms-server/wms-item/src/main/java/com/wms/item/domain/vo/ItemVo.java`
- 变更：
  - `ItemDto` 新增 `List<Long> binIds`。
  - `ItemVo` 新增：
    - `List<Long> binIds`
    - `List<ItemBinVo> binLocations`
    - `String binSummary`
- 说明：
  - `binIds` 用于编辑回填与提交。
  - `binLocations` 用于详情和表单展示。
  - `binSummary` 用于列表页简洁展示。

### 三、后端业务与接口改造

#### 1. 扩展物品服务接口

- 修改：`wms-server/wms-item/src/main/java/com/wms/item/service/ItemService.java`
- 新增方法：
  - `List<ItemBinOptionVo> listBinOptions()`
- 保留并扩展：
  - `page()` 返回带 `binSummary` 的记录。
  - `getById()` 返回完整 `binIds + binLocations`。
  - `create()` / `update()` 同步保存关联。
  - `delete()` 同步逻辑删除关联。

#### 2. 物品服务实现

- 修改：`wms-server/wms-item/src/main/java/com/wms/item/service/impl/ItemServiceImpl.java`
- 具体改造：
  - 注入：
    - `WmsItemBinMapper`
    - `WmsBinMapper`
    - `WmsCabinetMapper`
    - `WmsAreaMapper`
    - `WmsWarehouseMapper`
  - 在 `create()` 中：
    - 校验 `binIds` 中的每个库位是否存在且可用。
    - 保存物品后批量插入 `wms_item_bin`。
  - 在 `update()` 中：
    - 先校验新 `binIds`。
    - 逻辑删除旧关联，再批量插入新关联。
  - 在 `delete()` 中：
    - 与标签、图片一样，补充逻辑删除 `wms_item_bin`。
  - 在 `page()` 中：
    - 批量查询当前页所有物品的库位关联。
    - 批量组装库房/区域/存放柜/库位名称，避免 N+1。
    - 为每个物品填充 `binSummary`，摘要格式固定为 `库房/区域/存放柜/库位编码`，多个以 `，` 连接。
  - 在 `getById()` 中：
    - 返回完整 `binIds` 与 `binLocations`。
  - 新增私有辅助方法：
    - `validateBinIds(List<Long> binIds)`
    - `saveItemBins(Long itemId, List<Long> binIds)`
    - `assignBins(Long itemId, List<Long> binIds)`
    - `buildItemBinMap(Set<Long> itemIds)`
    - `buildBinLocationVos(...)`
    - `buildBinSummary(List<ItemBinVo> locations)`
- 校验规则：
  - 库位不存在 -> `BizException("库位不存在")`
  - 库位已删除 -> `BizException("库位已删除")`
  - 库位已禁用 -> `BizException("库位已禁用")`
  - 重复 `binId` 在服务层去重，避免重复插入与前端重复选择导致唯一索引冲突。

#### 3. 物品控制器扩展

- 修改：`wms-server/wms-item/src/main/java/com/wms/item/controller/ItemController.java`
- 新增查询接口：
  - `GET /item/items/bin-options`
- 注解要求：
  - `@PreAuthorize("isAuthenticated()")`
  - `@DataScope`
- 返回：
  - `R<List<ItemBinOptionVo>>`

#### 4. 转换器最小补充

- 修改：`wms-server/wms-item/src/main/java/com/wms/item/converter/ItemConverter.java`
- 变更：
  - 保持原有基础字段转换。
  - 仅负责 `WmsItem -> ItemVo` 的基础字段，不把多表库位拼装塞进 Converter；库位聚合在 `ItemServiceImpl` 内完成，避免 Converter 过度承担查询逻辑。

### 四、前端 API 与类型改造

#### 1. API 扩展

- 修改：`wms-web/src/api/item/item.ts`
- 新增方法：
  - `getItemBinOptions()`
- 调整使用：
  - 编辑时调用 `getItem(id)` 获取完整详情，而不是只用列表行对象。

#### 2. 类型扩展

- 修改：`wms-web/src/types/item.d.ts`
- 变更：
  - 新增 `WmsItemBinVo`
  - 新增 `WmsItemBinOptionVo`
  - `WmsItemDto` 新增 `binIds: number[]`
  - `WmsItemVo` 新增 `binIds?: number[]`、`binLocations?: WmsItemBinVo[]`、`binSummary?: string`
- 说明：
  - 只补本次功能直接需要的字段，不趁机大面积清理当前 `spec/specModel`、`stockQty/currentStock` 等历史字段漂移。

#### 3. API 测试

- 新增：`wms-web/src/api/item/item.spec.ts`
- 覆盖点：
  - `getItemBinOptions()` 请求路径正确。
  - 现有 `getItem` / `addItem` / `updateItem` 在新增 `binIds` 后仍保持原路径不变。

### 五、前端页面改造

#### 1. 列表展示当前库位

- 修改：`wms-web/src/views/item/list/index.vue`
- 改造内容：
  - 在表格中新增“当前库位”列。
  - 显示策略：
    - 有绑定时显示 `row.binSummary`
    - 无绑定时显示 `未绑定`
    - 内容过长用 `el-tooltip` 承载完整文本。

#### 2. 新增/编辑表单支持多库位选择

- 修改：`wms-web/src/views/item/list/index.vue`
- 表单设计：
  - 新增 `binIds` 字段。
  - 使用 `el-select` 的 `multiple + filterable + collapse-tags` 方案。
  - 选项文案直接使用后端返回的 `displayLabel`，格式统一为 `库房 / 区域 / 存放柜 / 库位编码`。

  - 新增时默认空数组。
  - 编辑时先调 `getItem(id)`，再回填 `binIds`、`tagIds`、`images` 等详情字段。

#### 3. 页面数据加载

- 修改：`wms-web/src/views/item/list/index.vue`
- 变更：

  - `handleEdit()` 改为异步方法，先取详情再开弹窗。
  - `handleSubmit()` 提交 DTO 时带上 `binIds`。

### 手工验收

- 数据库执行迁移后，`wms_item_bin` 表存在且索引正确。
- 进入物品列表页：
  - 现有绑定过库位的物品能展示“当前库位”摘要。
  - 未绑定物品显示 `未绑定`。
- 新增物品：
  - 可从跨仓库的多库位选项中选择多个库位。
  - 保存成功后列表可看到摘要。
- 编辑物品：
  - 能正确回显已绑定库位。
  - 重新选择后保存，旧绑定被替换为新绑定。
- 删除物品：
  - 物品逻辑删除后，其 `wms_item_bin` 关联也被逻辑删除。

## Risks & Notes

- `wms-item` 引入 `wms-warehouse` 依赖后，需要关注模块循环依赖；本方案只让 `wms-item -> wms-warehouse` 单向依赖，不在仓库模块反向引用物品模块。
- 当前前端 `item` 类型与后端字段存在历史漂移；本次仅补足库位功能所需字段，避免把计划扩散成整页重构。
- 若线上库位数量非常大，后续可把 `bin-options` 升级为带关键字查询的远程搜索接口；本次先按全量活动库位下发实现。
