# 2.5D视图、详情、定位与布局编辑器 Spec

## Why
第 18 个功能已经提供了 2D 库房图形展示，但当前仍停留在只读浏览层，缺少视角切换、详情钻取、快速定位和可保存的布局编辑能力。要真正形成可用的库房可视化工作台，需要把第 19、20、21、22 个功能作为一组联动能力一起落地。

## What Changes
- 在现有 2D 可视化页面上增加 2D / 2.5D 视图切换能力，使用统一数据模型驱动两种视图。
- 增加存放柜详情弹窗，展示当前存放柜及其库位统计、状态和基础信息。
- 增加快速定位与高亮能力，支持按区域、存放柜、库位编码快速聚焦并高亮目标。
- 增加库房布局编辑器，支持在可视化页面中调整存放柜布局并持久化保存。
- 后端补齐布局持久化所需的最小能力，以“存放柜位置与排序持久化”为主，不在本轮引入区域级坐标编辑。

## Impact
- Affected specs: 2.5D 视图切换、存放柜详情弹窗、快速定位、高亮、库房布局编辑器
- Affected code: `wms-web/src/views/warehouse/visual/**`、`wms-web/src/api/warehouse/*.ts`、`wms-web/src/types/warehouse.d.ts`、`wms-server/wms-warehouse/**`

## ADDED Requirements
### Requirement: 2D/2.5D 视图切换
系统 SHALL 在同一库房可视化页面中提供 2D 与 2.5D 两种浏览视图，并保持相同的选中上下文。

#### Scenario: 切换到2.5D视图
- **WHEN** 用户在库房可视化页面切换到 2.5D 视图
- **THEN** 系统使用与 2D 视图相同的区域、存放柜、库位数据生成 2.5D 展示
- **AND** 当前已选中的区域、存放柜、库位保持同步

#### Scenario: 切回2D视图
- **WHEN** 用户从 2.5D 视图切回 2D 视图
- **THEN** 系统保留当前选中对象和高亮状态
- **AND** 不重新丢失用户的浏览上下文

### Requirement: 存放柜详情弹窗
系统 SHALL 支持从可视化页面打开存放柜详情弹窗，查看当前存放柜的结构与摘要信息。

#### Scenario: 点击存放柜查看详情
- **WHEN** 用户点击某个存放柜并触发详情操作
- **THEN** 系统展示该存放柜的名称、编码、所属区域、行列规模、状态、库位数量等摘要信息
- **AND** 展示库位使用情况或基础统计

#### Scenario: 存放柜无库位数据
- **WHEN** 当前存放柜尚未配置任何库位
- **THEN** 详情弹窗明确提示“暂无库位数据”
- **AND** 不展示误导性的空白内容区

### Requirement: 快速定位与高亮
系统 SHALL 支持按编码快速定位区域、存放柜或库位，并在画布中聚焦高亮目标。

#### Scenario: 按存放柜编码快速定位
- **WHEN** 用户输入存放柜编码并执行定位
- **THEN** 系统选中对应存放柜
- **AND** 其所属区域同步高亮
- **AND** 画布自动聚焦到该存放柜附近

#### Scenario: 按库位编码快速定位
- **WHEN** 用户输入库位编码并执行定位
- **THEN** 系统选中该库位
- **AND** 自动同步其所属存放柜与区域
- **AND** 在当前视图中对目标库位进行明显高亮

#### Scenario: 定位目标不存在
- **WHEN** 用户输入的区域、存放柜或库位编码不存在于当前库房
- **THEN** 页面提示未找到目标
- **AND** 不清空当前已有选中上下文

### Requirement: 布局编辑器与持久化
系统 SHALL 提供可编辑并持久化保存的库房布局编辑器，用于维护存放柜在区域内的展示位置。

#### Scenario: 进入布局编辑模式
- **WHEN** 用户在可视化页面开启布局编辑
- **THEN** 系统进入编辑模式
- **AND** 存放柜显示可拖拽或可调整位置的交互状态
- **AND** 普通浏览交互被限制为编辑相关操作

#### Scenario: 保存布局成功
- **WHEN** 用户完成存放柜布局调整并点击保存
- **THEN** 系统将当前存放柜位置与排序信息持久化到后端
- **AND** 保存成功后退出或保持编辑模式时都可重新渲染最新布局

#### Scenario: 保存布局失败
- **WHEN** 布局保存接口失败
- **THEN** 页面提示保存失败原因
- **AND** 保留当前未保存布局，允许用户继续调整或重新尝试

### Requirement: 后端布局存储最小能力
系统 SHALL 以存放柜为粒度提供布局持久化能力，支撑前端布局编辑器保存结果。

#### Scenario: 批量保存存放柜布局
- **WHEN** 前端提交某库房或某区域下的存放柜布局结果
- **THEN** 后端批量更新对应存放柜的 `positionX`、`positionY` 及稳定排序字段
- **AND** 后续查询可返回保存后的布局结果

#### Scenario: 柜体缺少显式位置
- **WHEN** 某些存放柜尚未保存 `positionX`、`positionY`
- **THEN** 系统在读取布局时回退到推导式布局
- **AND** 不阻塞 2D / 2.5D 浏览功能

## MODIFIED Requirements
### Requirement: 库房可视化页面结构
系统 SHALL 将现有 2D 可视化页面升级为可扩展的库房可视化工作台，而不是单一只读画布页。

#### Scenario: 工作台具备多种操作区
- **WHEN** 用户进入库房可视化页面
- **THEN** 页面提供视图切换、快速定位、详情查看和布局编辑入口
- **AND** 现有区域、存放柜、库位联动逻辑继续可用

### Requirement: 布局渲染优先级
系统 SHALL 优先使用持久化布局信息渲染存放柜位置，并在缺失时回退到推导布局。

#### Scenario: 已保存布局优先
- **WHEN** 某存放柜已存在持久化的布局位置
- **THEN** 页面渲染时优先采用保存值
- **AND** 不再仅依赖推导式顺序布局

## REMOVED Requirements
### Requirement: 19-22 仅作为前端静态增强
**Reason**: 用户已明确要求第 19、20、21、22 个功能一次性完整落地，其中第 22 个功能需要可编辑并持久化，而不是只做演示级前端效果。
**Migration**: 在保留 18 号功能已有只读能力的基础上，补齐视图切换、详情、定位和布局持久化能力，形成完整的可视化工作台。
